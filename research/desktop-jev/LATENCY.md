# LATENCY — 每一步到底多快，以及"最快能多快"

> 2026-11-09 实测。全部数字来自本机（RTX 5070 Ti **Laptop 11.9GB**、torch 2.11+cu128、
> 2560×1600 单屏），脚本：`scripts/bench_latency_budget.py`、`scripts/probe_model_opts.py`、
> `scripts/probe_attn_mask.py`，原始 JSON：`assets/bench/latency_20261109.json`、
> `assets/bench/model_opts_20261109.json`。
>
> ⚠️ PROGRESS 里写的"16GB"是错的，`torch.cuda.get_device_properties(0).total_memory`
> 报 **11.9 GiB**。

## 1. 硬件天花板（实测，不是手册值）

| 项 | 实测 | 说明 |
|---|---|---|
| bf16 matmul | **48.1 TFLOPS** | 4096³、p50 2.86ms |
| fp16 matmul | 44.3 TFLOPS | 明显比 bf16 差，没有理由用 fp16 |
| 显存带宽 | **521 GB/s** | 256MiB copy（读+写）折算 |
| SMs | 46 | Blackwell |
| 带外 | `flash_attn` **未安装** | 所以只有 sdpa / eager 两条路 |

模型的物理下限（0.6B、权重 bf16 = 1.2GB）：
- **权重要读一遍**：1.2GB ÷ 521GB/s = **2.3 ms**（每次前向的绝对地板）
- **算力**：每 token 约 1.2 GFLOP，N 个 token 的 prefill = 1.2e9·N FLOP
  → 1653 token = 1.98 TFLOP ÷ 48.1 TFLOPS = **41 ms**

## 2. 现状预算（一次真实决策步）

| 环节 | 实测 p50 | 占比 | 备注 |
|---|---|---|---|
| UIA 观测（前台窗口重走） | **137 ms** | 40% | 冷启动 423ms；`force_full` 403ms；节点 296 个 |
| 状态位读取 | 8–10 ms | 3% | 只读最终保留下来的元素 |
| Jev 决策（84 元素 / 1653 token） | **180 ms** | 53% | 优化前 285ms，见 §4 |
| 注入（SendInput） | **0.03 ms** | ~0 | 空移动实测，真正成本在应用响应 |
| pyautogui 固定开销 | ~20 ms/click | 6% | `PAUSE=0.02`，每次调用后固定 sleep |
| **一次左键步合计** | **~340 ms** | | 与离线复测的真实域 p50 487ms 同量级（那轮 sdpa + 长表） |

其它实测：
- 截图（GDI BitBlt，2560×1600）：**65.5 ms**；缩放 1280 再 JPEG：+16ms；
  `capture_for_model` 全程 **95 ms**。纯视觉路线每步都要交这笔钱。
- 右键：`right_click` 固定睡眠 80+120+120ms + 3 次 pyautogui PAUSE ≈ **380 ms**
  （CAA 需要这段间隔，但它只在右键步付，不影响左键步）。
- 元素表长度 → 决策成本（同一模型、同一台机器）：

| 元素数 | token | 决策 p50 |
|---|---|---|
| 20 | 381 | **39 ms** |
| 40 | 788 | **85 ms** |
| 84 | 1653 | **180 ms**（优化后） |
| 99 | 1997 | 412 ms（优化前测量） |

**token 数是决策成本的唯一主变量**，而且是超线性的（84→40 元素：token ×0.48，时间 ×0.47；
40→20：时间再 ×0.46）。

## 3. 理论上最快是多少

分三档，每档都给出**机制性依据**，不是猜测：

### 3.1 绝对地板：宏回放（不问任何模型）

一步 = 注入 + 应用自己响应。

```
0.03 ms（SendInput）
+ 10–50 ms（应用处理点击/重绘；Windows 消息循环 + 焦点切换的量级）
≈ 10–50 ms/步  →  20–100 步/秒
```

这是**任何** GUI agent 都无法绕过的地板：只要动作要落到别的进程里，就得等它反应。
人类 1–3 s/步 → 这条路线理论上比人快 **20–300×**，但只能覆盖已录制过的任务。

### 3.2 结构化路径地板（UIA 观测 + 小模型决策，本项目的形态）

```
观测：3–15 ms      ← 前提是 IUIAutomationCacheRequest（一次跨进程调用取整棵子树的属性）
                      或事件驱动的增量更新。现在是每节点一次 COM 往返（0.46–0.75ms/节点）
决策：2–41 ms      ← 20 候选 + 0.1B encoder ≈ 2–5ms；84 元素 + 0.6B 的算力地板 = 41ms
注入：0.03 ms
响应：10–50 ms
≈ 15–105 ms/步
```

把三档写成表：

| 配置 | 决策地板 | 决策现实（batch=1，MFU 25–50%） | 一步合计 |
|---|---|---|---|
| 84 元素 + 0.6B（现状架构） | 41 ms | **80–140 ms** | ~105–175 ms |
| 20 元素 + 0.6B（学出来的短名单） | 10 ms | 25–40 ms（已实测 39ms） | ~50–90 ms |
| 20 元素 + 0.1B encoder | 2 ms | 5–10 ms | **~20–65 ms** |
| 宏回放（无模型） | 0 | 0 | **10–50 ms** |

**结论：结构化路径的天花板不在模型，在观测。** 模型侧从 180ms 压到 40ms 是"换个形态"的量级
（短名单/小模型），再往下压不动；而观测侧 137ms → 5–15ms 是 10× 的空间，成本是工程
（CacheRequest + 增量），不是算力。

### 3.3 视觉路径地板（截图进 VLM）

```
截图：5–10 ms（DXGI Desktop Duplication） / 65 ms（现在用的 GDI BitBlt）
图像编码：896px 进 0.5B 级 VLM ≈ 30–80 ms（本地）
决策：小 VLM 1 步 ≈ 20–60 ms
≈ 40–80 ms/步（本地小 VLM，且必须常驻）
```

一旦走**云端 API**，地板就变成网络 + 排队：实测这一层的 VLM 决策 p50 **5978 ms**。
所以"用大模型每步看一眼"这种形态，物理上就不可能进 100ms 级——
它不是"还没优化好"，是**架构上离地板两个数量级**。

## 4. 已经落地的加速（2026-11-09，零精度变化）

1. **`attn_implementation="eager"`**：本机 eager 比 sdpa 快 **1.5×**（1653 token：285→185ms）。
   Qwen3 的 QK-norm + head_dim=128 在这张卡上让 sdpa 走不到快内核。
   mask 形态（float32 全 1 / bool / None）实测无差别，不是 mask 的锅。
2. **`torch.inference_mode()`**：再省 2–5%。
3. **加载后预热一次前向**：把 CUDA context / cuBLAS handle / 分配器池预热掉。
   这是离线复测里 **p95 10.3s vs p50 487ms** 的来源——第一次真决策吃掉了初始化。
   预热后实测：首次决策 **189ms**，p50 180ms / p95 231ms（84 元素）。

净效果（一次 84 元素决策）：**285 ms → 180 ms（−37%）**，且尾延迟从 10.3s 级降到 0.26s 级。

## 5. 还没做、但按收益排序的加速项

| # | 改动 | 预期 | 成本/风险 |
|---|---|---|---|
| 1 | **候选短名单**（84→20，学出来的） | 决策 180→40ms，一步 340→190ms | 要训练一个打分器；BENCH §9.2 |
| 2 | **UIA CacheRequest / 增量观测** | 观测 137→5–15ms，一步再 −120ms | 纯工程，要换掉 `uia_tree` 的遍历方式；不碰模型 |
| 3 | **DXGI 截图**（若走视觉路线） | 65→5–10ms | 换 mss→dxcam；坐标体系不变 |
| 4 | 表格式再压（16 字名 + 空格 + 类型码） | token −20~30%，决策 −15~25% | 改格式=改训练分布，要重训 |
| 5 | pyautogui PAUSE / 右键固定睡眠 可配 | 20–380ms/次 | 可靠性风险，建议只在"确认稳定"的调用点放宽 |
| 6 | 常驻进程（模型/UIA 常驻） | 省 8–36s 冷启动 | 对短任务收益最大 |

## 6. 一句话

现状 **~340 ms/步**（不升级）、**~6.2 s/步**（真实域 98% 升级到 VLM）；
结构化路线的物理地板 **~20–65 ms/步**，宏回放 **10–50 ms/步**；
人类 1–3 s/步。**离地板最近的一步不是换更大的模型，而是把观测从 137ms 压到 10ms。
