# 文献空白分析（desktop-jev / gaps）

> 配合 literature.md 阅读。回答三个问题：现有工作没解决什么？desktop-jev 是否有先例？学术风险在哪？

## 1. 现有文献没解决的问题

**a) GUI agent 的"步级决策"从未被小模型化、校准化。**
现有小模型化努力全在 **grounding**（OS-Atlas/UGround/ShowUI：把"指哪"解耦给 2–7B 模型），
而每步"做什么"（点/滚/等/完成/认输 + 置信度）的决策权始终握在大模型手里——
即使接了 grounding 小模型，循环仍每步一次大模型前向。
**"把步级决策本身做成 0.5–1.5B 的校准分类器"在 GUI 文献中没有对应物。**
Jev 证明了这个形态在文本决策域成立，但其无图像、无 UI 结构输入、无动作空间设计。

**b) 桌面（Windows/UIA）域的结构化观测没人喂给决策模型。**
Web 域的 agent 小模型工作（若有）吃 DOM；桌面 grounding 工作吃截图。
UIA 元素表作为决策模型的**唯一观测**（不走像素）未见先例——
而 ScreenSpot-Pro（桌面专业软件纯视觉 grounding 仅 ~19–48%）恰恰说明
桌面域的结构化杠杆比 Web 更值钱：像素路线在桌面是硬上限，UIA 不是。

**c) "小模型→大模型"的校准升级，作为系统设计无人做。**
选择性预测（learning to defer）有完整理论（Geifman & El-Yaniv 2017），
Jev 的 cookbook 有 auto_accept/review_at/block_at 阈值实践，
Agent S2 有失败换专家——但三者没有交汇：
**用校准置信度驱动"快模型执行 / 慢模型接管"的步级路由，并系统性量化
（覆盖率 vs 升级率 vs 端到端成功率）**，GUI agent 文献缺位。
最接近的是 Jev 自己的阈值机制，但那是文本工作流，不是具身动作序列。

**d) 桌面域连"动作分布统计"这种基础数据都没有。**
Web 有 Mind2Web/WebArena 轨迹统计（click+scroll >60%）；
桌面（Windows）没有任何公开的真实任务动作分布。
"无文本步占比"——本设计覆盖率假设的地基——是个无人测量过的量。

## 2. desktop-jev 的先例分析

方案三件套：**UIA 结构化观测 + 收窄动作集的并行输出头 + 校准置信度升级协议**。

- **UIA 观测**：部分先例。WindowsAgentArena 的 Navi agent 用 UIA/a11y 树（但其决策
  仍是大模型）；experience-replay 的语义锚点同源于 UIA 稳定性。把 UIA 表作为
  **小模型的唯一输入模态**未见先例。
- **并行输出头**：先例在文本域（Jev）和 robotics action tokenization
  （OpenVLA-OFT 的并行解码证明砍自回归是可行的加速路径，arXiv 2502.19645）。
  GUI 步级决策的四头设计（操作/元素/槽位/置信度）是新的组合。
- **校准升级**：选择性预测理论 + Jev 阈值实践是先例，**应用于 GUI 动作序列**未见发表。
- **结论：组合层面没有先例。** 单独组件各有远亲，但"UIA 观测 → 0.5–1.5B 校准
  步级决策器 → 低置信升级 VLM"的端到端闭环是新的，恰好补上 §1a/§1b/§1c。
  与 experience-replay 合观：screen-use 的三级 cascade（宏/小模型/VLM）=
  "Voyager 技能库 + Jev System One + 选择性预测"在 Windows GUI 域的统一实现。

## 3. 学术风险诚实清单

1. **范式来源未经独立验证**。Jev 的全部数字是厂商自报，参照系不是 ground truth，
   架构未发表。若 Jev 范式在复现中不成立，本设计的架构根基动摇——
   缓解：我们只用其"并行类型化输出 + 校准目标"思想，这两点有独立文献支撑
   （Guo 2017 校准、OpenVLA-OFT 并行解码）。
2. **覆盖率假设可能证伪**（§1d）：无文本步占比无人测过。若真实桌面任务
   文本步占比 >40%，或 UIA 观测上小模型准确率 <80%，70–90% 的 VLM 削减目标不成立。
   缓解：阶段 1 设 kill criterion，数据先行。
3. **桌面无 MiniWoB++ 等价物**，合成环境的 sim-to-real gap 未知。
   MiniWoB++→真实 Web 的迁移在 Web 域已证明有限（WebShop：模拟 29% vs 真实更低）；
   桌面 mock 应用（tkinter/Qt）到真实 Win32 应用的迁移没有任何文献证据。
   缓解：腿 1（真实轨迹）与腿 2（合成）混训，以真实任务集为唯一验收。
4. **校准在分布漂移下退化**。temperature scaling 假设留出集与在线同分布；
   桌面环境（新应用、版本更新）天然漂移。τ 需要在线再校准机制——文献成熟
   （滑动窗口 ECE 监控），但工程量要算进阶段 4。
5. **"升级即标注"有选择偏差**：困难样本全来自小模型认输处，若教师只对认输样本
   标注，训练分布会自我强化（越不学越不会）。缓解：定期对快路径成功样本
   抽样送教师审计（探索-利用权衡）。
6. **贡献定位风险**：若 OS-Atlas 系工作下一步自然延伸到"步级决策头"，
   §1a 空白会快速被填。先发窗口有限——这是尽快完成阶段 0–3 的论据，
   也是把"Windows/UIA 域 + 校准升级协议"（而非"小模型做 GUI 决策"本身）
   作为贡献核心的论据。
